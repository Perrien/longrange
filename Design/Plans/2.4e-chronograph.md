# Plan — Task 2.4e: Chronograph (record true MV per rifle+lot)

`Status: BUILT 2026-07-24 — owner-approved, code-complete, gates green (typecheck / 405 tests / build / golden 36-0). AWAITING OWNER device sign-off. See Design/execution/PROGRESS.md task 2.4e. Not committed (git left to owner).`

## Context

The DOPE/truing loop (feature-catalog §D) needs the player to **measure the true muzzle
velocity** of their actual rifle+lot — the box number is only a believed value, and the
hidden truth (per-instance MV offset + per-lot mean shift + per-shot SD) is what the
rifle really shoots. The chronograph is the in-game instrument that reveals it: deploy
it, fire a string, and read the measured **average / SD / extreme-spread** the box never
told you. This is the **MV lever** of solver truing (2.5, D11 — chrono → effective MV);
2.5 later fits BC from a confirmed node once MV is pinned.

2.4e is independent of the node/confirm flow (2.4d) and of the DOPE range (2.4b/c). It
also directly answers the earlier "show me evidence it's working" ask: the chrono panel
displays **measured MV vs box MV**, which is the visible proof the true model is live.
This plan implements **only 2.4e**. Work stops after it for sign-off (owner task-loop rule).

## Scope (from `increment-2.4-plan.md` §2.4e + decision D10)

## Design decisions (resolved)

- **MV source: thread the real fired shot's MV (D10 preferred branch) — VERIFIED in C++.**
  `match/simulator.cpp:52-53` draws each shot's MV as
  `clipToThreeSigma(Random::normal(nominal_mv, mv_sd), …)` and stores it as
  `SimulatedShot::actual_mv` (bound at `bindings.cpp:235`, typed `engine-bridge/types.ts`).
  The scatter sim is built with the **true mean MV** (`trueLoadOf` → `Load.muzzleVelocityMps`)
  and **true per-shot SD** (`dispersion.mvSdMps = truth.lot.mvSdMps`), so `actual_mv` per shot
  is a genuine independent draw from `N(trueMean, trueSD)` (3σ-clipped). `createScatterSimulator.fire()`
  (match-sim.ts:112-115) currently discards it. **Fix: `fire()` returns `{ x, y, mvMps }`**
  (read `shot.actualMv`). No C++ change, no seam-side RNG, no truth object leaves — a plain
  number, and it's the very MV that flew the bullet (internally consistent). The distribution-
  sanity test guards this behaviour against regression.

### Realism model (why this is honest — owner requirement 2026-07-24)

Each shot's MV is an **independent draw** from the lot's true distribution `N(trueMean, trueSD)`
(3σ-clipped, per the C++). Consequences the design must preserve:
- The persisted `ChronoSummary.avgMps` is the **running sample mean of actual readings** — an
  *estimate* of the true mean, **never snapped to truth**. Its standard error ≈ `trueSD/√N`:
  5 shots beats the box, but is still off; more shots tighten it with **diminishing returns**.
- `sdMps` is the **sample SD** of the readings — an estimate of the true per-shot SD (the box
  gives none), also improving with N.
- 2.5 truing therefore consumes an **imperfect measured MV**, so the player's MV knowledge
  stays honestly approximate — exactly the intended pedagogy. `mergeChronoString` must keep
  averaging real readings (never substitute the true mean).

- **`chronoSummaries` at `SaveData` top-level** (`chronoSummaries?: ChronoSummary[]`,
  parallel to `dopeNodes?`), keyed by `(rifleId, lotId)`. Additive-optional, no version bump.
- **Chrono `current` string + `deployed` flag are session-only**; only `summaries` persist.
  The persist subscription fires on **`state.chrono.summaries !== prev`** specifically (not
  the whole slice) so per-shot appends to the live string don't hammer IndexedDB.
- **Velocity units: m/s (MIL) / fps (MOA)** via `mpsToFps` + the `unitsPrimary` toggle —
  NOT `formatSpeedForDisplay` (that's mph, for wind).

## Implementation checklist

### 1. `engine-bridge/match-sim.ts` (+ `types.ts` if needed)
- Widen `ScatterSimulator.fire()` to return `{ x: number; y: number; mvMps: number }`
  (`mvMps: shot.actualMv`). `ScatterShot` (`{x,y}`) stays as-is — `resolveShot` takes it and
  the wider sample is structurally assignable (pass the variable, not a literal). Confirm
  `ESimulatedShot.actualMv` is in `types.ts`; add the field if missing (it is already bound
  C++-side, so no binding change / golden vectors untouched).

### 2. `game/chrono.ts` (new — pure, no engine, no `hidden-truth`)
- `stringStats(readings: number[]) → { shots, avgMps, sdMps, minMps, maxMps }` (sample SD;
  0 shots → zeros; 1 shot → sd 0; ES = max−min).
- `mergeChronoString(summaries, rifleId, lotId, readings, nowIso): ChronoSummary[]` — find
  the existing `(rifleId,lotId)` summary, **Welford parallel-combine** it with the new
  string (reconstruct `M2 = sd²·(n−1)` from the stored sd, combine, re-derive sd), take
  min/max across both, upsert into a **new** array (mirrors `upsertNode`). No existing
  summary → build from `stringStats`.
- `pruneChronoForRifle` / `pruneChronoForLot` (cascade helpers).

### 3. `persistence/schema.ts` + `index.ts` + `migrations.ts`
- `ChronoSummary` interface (`rifleId, lotId, shots, avgMps, sdMps, minMps, maxMps,
  updatedAtIso`) + top-level `chronoSummaries?: ChronoSummary[]` (additive-optional, NO
  version bump — mirror `dopeNodes?`). `validateChronoSummary` present-only block;
  `DEFAULT_SAVE.chronoSummaries: []`; export `ChronoSummary`; migrations.ts comment
  (additive-optional, no migration).

### 4. `state/store.ts`
- `ChronoState { deployed: boolean; current: { rifleId; lotId; readings: number[] } | null;
  summaries: ChronoSummary[] }` + `defaultChrono()`; add `chrono` to `GameStore` + initial
  state. Actions:
  - `setChronoDeployed(on)`.
  - `logChronoReading(rifleId, lotId, mps)` — if `current` belongs to different gear,
    auto-commit it into `summaries` first; then append/start the string. (Only mutates
    `current` in the common case → summaries ref unchanged → no persist.)
  - `commitChronoString()` — merge `current` into `summaries` via `mergeChronoString`, clear
    `current` (the "new string" button).
  - `applyChrono(chrono)` hydration.
  - Cascade: extend `deleteRifle`/`deleteLot`’s existing `set()` to also prune `summaries`
    (`pruneChronoFor*`) and null a `current` that belonged to the deleted gear.

### 5. `state/persist-settings.ts` + `state/index.ts`
- `saveToChrono(save) → { deployed:false, current:null, summaries: save.chronoSummaries ?? [] }`;
  `storeToSave` carries `chronoSummaries: state.chrono.summaries`; `loadSettingsInto` calls
  `applyChrono`; subscribe predicate gains `|| state.chrono.summaries !== prev.chrono.summaries`.
  Export `defaultChrono`/`ChronoState`/`saveToChrono`.

### 6. `scope/ScopeView.tsx` (reading wiring — both fire paths)
- **fireSteel (~790):** hoist `const shot = simAt(rangeM, gearCtx).fire();` (pass `shot` as
  `scatter`); after `recordShot`, if `store().chrono.deployed && gearCtx` →
  `store().logChronoReading(gearCtx.rifle.id, gearCtx.lot.id, shot.mvMps)`.
- **fireSightIn (~1061):** the `ctx` branch already samples `sightInScatterAt(...)` (a gear
  scatter, so it carries `mvMps`); when `store().chrono.deployed && ctx` →
  `logChronoReading(rifle.id, lot.id, scatter.mvMps)`. Box-fallback (`{x,y:0}`, no gear) logs
  nothing — the chrono needs a rifle+lot.
- Add `<ChronoPanel />` to the HUD column (shown on both scene types).

### 7. `scope/ChronoPanel.tsx` (new — mirrors DopePanel structure; NO engine load needed)
- Reads store `chrono` + active rifle/lot + `unitsPrimary`. **Deploy** toggle button
  (`setChronoDeployed`). When deployed and gear active: live per-shot readings + running
  `stringStats(current.readings)` avg/SD/ES (m/s or fps via `mpsToFps`), a **New string**
  button (`commitChronoString`), and the persisted summary for the active `(rifle,lot)`
  **beside the box MV** (`getAmmoLoad(lot.catalogId).believedMvMps`). No active gear →
  "select a rifle + lot to chronograph". Inline styles like DopePanel.

## Recommended signatures

```ts
// persistence/schema.ts
export interface ChronoSummary {
  rifleId: string; lotId: string;
  shots: number; avgMps: number; sdMps: number; minMps: number; maxMps: number;
  updatedAtIso: string;
}
// game/chrono.ts
export function stringStats(readings: number[]): { shots: number; avgMps: number; sdMps: number; minMps: number; maxMps: number };
export function mergeChronoString(summaries: ChronoSummary[], rifleId: string, lotId: string, readings: number[], nowIso: string): ChronoSummary[];
export function pruneChronoForRifle(summaries: ChronoSummary[], rifleId: string): ChronoSummary[];
export function pruneChronoForLot(summaries: ChronoSummary[], lotId: string): ChronoSummary[];
// engine-bridge/match-sim.ts
fire(): { x: number; y: number; mvMps: number };
```

## Tests

- **`game/chrono.test.ts`** (pure): `stringStats` (0/1/n shots, ES=max−min); `mergeChronoString`
  == single-pass mean/SD/min/max over the concatenation of both strings (≤1e-9); first-string
  from empty; ES across strings; prune helpers.
- **`engine-bridge/match-sim.test.ts`** (real WASM, seeded): a chrono string's mean ≈ true
  mean MV and **sample SD ≈ lot true `mvSdMps`** (the D10 "distribution sanity" gate — proves
  `actual_mv` tracks the per-shot dispersion, per simulator.cpp:52-53; use a tolerance for the
  3σ clip); **the standard error of the running mean shrinks with N** (e.g. a 20-shot average
  is closer to the true mean than a 3-shot average, over seeded repeats) — the realism
  requirement; `fire()` returns finite `mvMps`.
- **`persistence.test.ts`**: `chronoSummaries` round-trip fixture; pre-2.4e save still loads;
  reject a non-finite `avgMps`.
- **`state.test.ts`**: deploy toggle; `logChronoReading` appends; gear-switch auto-commit;
  `commitChronoString` merges + clears; cascade prunes summaries on `deleteRifle`/`deleteLot`;
  persist→reload keeps `summaries`, resets `deployed`/`current`.
