## Context

The DOPE/truing loop (feature-catalog §D) is the game's identity: the player
confirms real come-ups at distance (**nodes**), a chronograph measures true MV, and a
Data Book shows the believed curve vs. confirmed reality. The full increment was
planned as **2.4a–f + 2.5** (decisions D1–D14 locked in
`Design/archive/increment-2.4-plan.md`). Nothing is built yet.

**2.4a is the foundation everything else writes to:** the node data model, the
confidence rule, the range-ladder generator, and the persistence for confirmed nodes.
It is *pure data + rules* — **no UI, no gameplay flow** (those are 2.4d confirm-flow /
2.4f Data Book). Building it first means the confirm-node interaction (2.4d) and the
Data Book (2.4f) have a validated store slice + schema to build against.

This plan implements **only 2.4a**. Per the owner's task-loop rule, work stops after
this sub-task for sign-off before anything advances.

## Design decisions (resolved)

- **σ_v(R): analytic approximation (owner's call, 2026-07-24).** No WASM. First-order
  vacuum-drop proxy for velocity sensitivity: `sensitivityRad ≈ g·R·σ_V / V³` (g =
  9.80665, V = believed MV, σ_V = believed per-shot MV SD = `perShotMvSd.nom`),
  combined in quadrature with the range-independent inherent-precision term:
  `σ_v(R) = hypot(g·R·σ_V/V³, inherentPrecisionNomRad)`. Monotonic in R and in σ_V, and
  match grade < bulk at every range (smaller σ_V *and* tighter inherent precision) —
  satisfies D3's required shape. Constants provisional; the whole thing lives inside
  `dope-book.ts` so the module stays pure and WASM-free. **This drops the earlier idea
  of a believed-solve seam in `gear-solve.ts` — that file is untouched by 2.4a.**
- **dopeNodes live at `SaveData` top-level** (`dopeNodes?: DopeNode[]`, parallel to
  `rifles[]`/`ammoLots[]`). A node keys on both `rifleId` + `lotId`, so it belongs to
  the pairing, not one record; export/import inherits it via JSON with no `export-file`
  change.
- **Dedicated `dope` store slice** (not folded into `inventory`), so its lifecycle stays
  legible. The persistence predicate must be extended to watch it (see step 5).
- **Cascade in the same `set()` call** inside `deleteRifle`/`deleteLot` — atomic, no
  window where a node points at a deleted rifle, no extra subscription.

## Implementation checklist

### 1. `game/catalog.data.json` + `game/catalog.ts`
- Add `"effectiveRangeYd"` to each of the 4 cartridge objects (top level, beside
  `twist`): **.22 LR 200, .223 600, .308 1000, 6.5 CM 1200** (D7 provisional, yd).
- `catalog.ts`: add accessor `catalogEffectiveRangeYd(cartridgeId): number` (and/or an
  `-M` variant via the existing yd→m helper). Ladder generator consumes it by
  `cartridgeId`.

### 2. `game/dope-book.ts` (new — pure, no engine, no `hidden-truth`)
Exports:
- `DopeNode` interface (signature below).
- `believedVerticalSdRad(rangeM, mvMps, mvSdMps, inherentPrecisionRad): number` — the
  analytic σ_v(R) above. Pure numbers in/out.
- `requiredShots(sigmaVRad, tolRad?): number` = `clamp(ceil((sigmaVRad/tolRad)²), 3, 10)`;
  `TOL_RAD = milToRad(0.1)` exported const (provisional).
- `confidenceTier(node, sigmaVRad, tolRad?): 'noted'|'provisional'|'confirmed'` —
  `noted` if `hits < 1`; `confirmed` if `shots >= requiredShots(...)`; else `provisional`.
- `upsertNode(nodes, node): DopeNode[]` — replace-by-station (D5): drop existing node
  matching `(rifleId, lotId, distanceM)` within a 0.5 m epsilon, append new.
- `pruneNodesForRifle(nodes, rifleId)` / `pruneNodesForLot(nodes, lotId)`.
- `ladderStationsM(cartridgeId, isRimfire, units, effectiveRangeYd): number[]` — step
  set rimfire `[25,50,75,100,125,150,200]` else century `[100,200,…]`; interpret steps
  in the active display unit (yd for MOA → `yardsToMeters`, m for MIL); cap ≤
  effective range in that unit; entry-time resolution, no live-morph (2.3 D3).

### 3. `persistence/schema.ts`
- Add `DopeNode` interface + `dopeNodes?: DopeNode[]` on `SaveData` (additive-optional,
  **no `CURRENT_SCHEMA_VERSION` bump** — mirror `activeRifleId?`).
- Add `validateDopeNode(n, i)`; in `validateSaveShape` add a present-only block
  (`if (d.dopeNodes !== undefined) { array + forEach validate }`), mirroring the
  playerZero/rifles present-only pattern. Add `dopeNodes: []` to `DEFAULT_SAVE`.

### 4. `persistence/migrations.ts`
- No new migration. One-line comment: additive-optional field, old saves omit it and
  the loader defaults `[]` (playerZero/zeroRangeM precedent).

### 5. `state/store.ts` + `state/persist-settings.ts`
- store.ts: `DopeState { nodes: DopeNode[] }`, `defaultDope()`, `dope` on `GameStore`;
  actions `confirmNode(node)` (uses `upsertNode`), `deleteNode(rifleId, lotId, distanceM)`,
  `applyDope(dope)` (hydration). Extend the existing `deleteRifle`/`deleteLot` `set`
  updaters to also set `dope.nodes` via `pruneNodesForRifle/Lot` in the same object.

  otherwise dope changes never save).

### 6. `main.tsx`

## Recommended signatures

```ts
export interface DopeNode {
  rifleId: string; lotId: string;
  distanceM: number;                 // SI, the station shot
  elevationRad: number; windageRad: number;
  zeroRangeM: number;                // zero reference at confirm (stale-flag basis)
  shots: number; hits: number;
  conditions: { windSpeedMps: number; windDirectionDeg: number; tempC: number; pressurePa: number };
  confirmedAtIso: string;
}
export const TOL_RAD: number;                                        // milToRad(0.1), provisional
export function believedVerticalSdRad(rangeM: number, mvMps: number, mvSdMps: number, inherentPrecisionRad: number): number;
export function requiredShots(sigmaVRad: number, tolRad?: number): number;
export function confidenceTier(node: Pick<DopeNode,'shots'|'hits'>, sigmaVRad: number, tolRad?: number): 'noted'|'provisional'|'confirmed';
export function upsertNode(nodes: DopeNode[], node: DopeNode): DopeNode[];
export function pruneNodesForRifle(nodes: DopeNode[], rifleId: string): DopeNode[];
export function pruneNodesForLot(nodes: DopeNode[], lotId: string): DopeNode[];
export function ladderStationsM(cartridgeId: string, isRimfire: boolean, units: DisplayUnits, effectiveRangeYd: number): number[];
```
